of the unified suggestions view is stable. The initial refactor keeps the existing
DaxLogoManager driving the logo unchanged.

## Logo: remove toolbarCompensationOffset hack (deferred, decided to keep overlay)
The Dax logo correctly stays a single shared morphing OVERLAY (DaxLogoManager) — moving it into the
per-page UnifiedSuggestionsView would break the search↔duck.ai morph into two sliding logos. So the
overlay architecture stays. The only hack is `toolbarCompensationOffset` (manual downward nudge in
`UnifiedInputContentContainerViewController.daxVerticalOffset`) because the toolbar sits under the
input and offsets the keyboard-relative centering. Clean fix (deferred): anchor the centering guide's
bottom to the true available-area bottom instead of keyboardLayoutGuide.top + offset. Looks fine
currently, so deferred.

## Regression: favorites grid "jumps then disappears" on Search→Duck.ai switch
Repro: Search mode showing favorites → switch to Duck.ai (UTI input grows taller) → the favorites
grid repositions (jumps) into the changed available area, then disappears as the crossfade completes.
Mechanism (traced): `swipeContainerViewController(didSwipeToMode:)` → `refreshVisibleContent` runs
`updateEscapeHatchTopInset()` + `applyRequestedContentInset()`; the taller Duck.ai input changes the
inset on the STILL-VISIBLE outgoing search page mid-crossfade, so the embedded NTP re-lays-out before
it fades. Likely amplified by the search host pinning bottom to `keyboardLayoutGuide.topAnchor`
(definite-height fix) making NTP reflow on input/keyboard geometry change (legacy NTP used a looser
bottom constraint). FIX (needs log-first frame-level investigation, not a patch): defer/skip the inset
update for the outgoing page during a mode switch, or freeze the outgoing favorites layout during the
crossfade, or revisit the favorites-state host sizing so NTP doesn't reflow on the input-height change.
