# Reader mode prototype

This package extracts articles on device with trafilatura-swift at revision `2720048a7b71ea91efcc025fc3f6ed50da6a6d35`. The native library and Swift bindings use Apache 2.0. SwiftSoup 2.13.9 rebuilds extracted HTML with a semantic allowlist. The public result is an immutable `ReaderArticle`; callers cannot construct unsanitized articles.

Before opening Xcode or resolving Swift packages, run `SharedPackages/ReaderMode/ThirdParty/Trafilatura/prepare.sh` from the repository root. The script downloads and verifies the pinned official binary, then namespaces its headers to avoid a collision with Clibsodium. The [wrapper documentation](ThirdParty/Trafilatura/README.md) records source provenance and the packaging change. Generated binaries are ignored. A fresh CI checkout also needs this preparation step; this local prototype does not modify CI workflows.

The iOS prototype uses the `readerMode` remote subfeature, disabled by default and available through local feature flag overrides. For a local run, add `-ff.readerMode true` to the app scheme launch arguments. Remote rollout would require the `readerMode` subfeature under `iOSBrowserConfig` in the privacy-configuration repository. A tab samples its HTML every three seconds while visible, foregrounded, and without an offered article. Sampling stops once an article is offered and resumes after navigation, a URL change, web process termination, or a flag change. While an article is offered, the browsing menu shows a Reader Mode item above Find in Page. It rejects inputs over one MiB and DOMs above 50,000 elements. Unchanged snapshots skip native extraction. A shared actor serializes native extraction away from the main actor. These limits and the minimum 500 characters in two paragraphs are prototype policies, not measured accuracy or performance targets.

A separate, nonpersistent WKWebView displays the snapshot with JavaScript disabled. It applies the tab's tracker block lists when content blocking is enabled and uses the article URL as the base URL, so site-specific rules and allowlisted sites match the original page. Insecure image requests are upgraded to HTTPS. Closing Reader, or switching away from the tab, returns to the original DOM, scroll position, and history. User links navigate through the original tab. The reader allows images that pass the tracker block lists, which can contact image hosts with no referrer. Extraction does not upload page content. Scripts, forms, frames, event handlers, source sets, page styles, and unsupported URL schemes do not enter the reader document. The extractor can discard standalone links and flatten code whitespace. Embedded media is omitted; fallback text or links can survive extraction.

The native sampler avoids a persistent injected observer and its teardown across user-script replacements. It does serialize the visible DOM repeatedly, and newly inserted content can take three seconds plus extraction time to become available. A MutationObserver could reduce repeated work, but needs a separate lifecycle and authentication design. Measure sampling cost on real devices before choosing that approach for production.

Readability.js remains an alternative with a JavaScript extraction path and a different accuracy profile. No comparative benchmark was run here. Custom heuristics require continued maintenance of site behavior. WebKit's private reader APIs are excluded because of App Store compatibility risk. Native attributed-text rendering would require separate table, image, and code layout work. This prototype uses public WebKit APIs and a Rust static library, but has not passed an App Store review.

The fixtures verify real extraction of prose, images, code, and tables, rejection of a navigation page, and safe HTML rendering. They do not establish broad extraction accuracy. Device performance, binary size impact, production UI design, and extraction across a representative site corpus remain unmeasured. Telemetry and reader typography settings are outside this prototype.

Local verification passed with four package tests, seven iOS controller tests, an iOS simulator build, and strict SwiftLint. Simulator smoke checks covered opening and closing Reader, preserving the original scroll position, inline links, dynamic article insertion, nonarticle rejection, and the disabled flag. These checks used local fixtures on iPhone 17 Pro with iOS 27.0; physical devices and iPad were not exercised.
